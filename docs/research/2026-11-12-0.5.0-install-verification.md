# FrontierMCP 0.5.0 install verification

Date: **2026-11-12**. Answers: is it safe to move the public install pin and bootstrap download from
0.4.0/0.4.1 to the published `frontier-mcp@0.5.0`, and on what evidence? Host: **macOS arm64**
(Darwin 27.2.0, Apple M4 Pro). Supersedes the pin choice in
[the 0.4.1 bootstrap verification](./2026-09-17-0.4.1-bootstrap-verification.md); that record stays
the evidence for 0.4.0 and 0.4.1.

## Published artifact

```text
https://registry.npmjs.org/frontier-mcp/-/frontier-mcp-0.5.0.tgz
SHA-256 6539109f4c3041ee99123e387dd19ff2bfbc5a78920cf97809fbbaee512e7f13
```

The extracted `package/scripts/frontier-setup.cjs` is byte-identical to `scripts/frontier-setup.cjs`
at `v0.5.0`. It identifies itself as bootstrap revision 2, the same revision 0.4.1 shipped.

## POSIX quick-start, preview only

Every run used an isolated `HOME` under a scratch directory, so neither the real
`~/.cursor/mcp.json` nor the real user-data directory was read or written. `--apply` was never
passed. The commands were the guide's POSIX quick-start with the 0.5.0 tarball and `--version 0.5.0`,
without `--apply`:

```sh
SETUP_DIR="$(mktemp -d)"
curl -fsSL https://registry.npmjs.org/frontier-mcp/-/frontier-mcp-0.5.0.tgz \
  -o "$SETUP_DIR/frontier-mcp-0.5.0.tgz"
tar -xzf "$SETUP_DIR/frontier-mcp-0.5.0.tgz" -C "$SETUP_DIR" \
  package/scripts/frontier-setup.cjs
node "$SETUP_DIR/package/scripts/frontier-setup.cjs" --version 0.5.0
```

1. **Node 24.15.0 running the bootstrap.** Exit 0 in 4.3s. It selected the current Node 24.15.0,
   read the engine range `^20.20.2 || ^22.17.1 || ^24.15.0`, installed into
   `$HOME/Library/Application Support/frontier-mcp/0.5.0/installed-<id>/`, passed MCP initialization
   and `tools/list`, printed a `frontier` entry with an absolute launcher and empty `args`, and ended
   `Preview only. Add --apply to write this Cursor entry.` No `$HOME/.cursor` directory was created.
2. **Node 16.20.2 running the bootstrap**, from a project holding `.node-version` (`16.20.2`),
   `package.json` with `packageManager: "bun@1.3.14"`, and `.scratch/`, with `--node` set to Node
   24.15.0 and `--bun` set to Bun 1.3.14. Exit 0; it reused the verified installation and printed the
   same preview. The project kept exactly its three entries.

Preview writes only the immutable installation directory (package, selector, launcher) and the
package manager's caches under `HOME`, plus a disposable preflight directory under the OS temp
directory.

## Server checks on the installed 0.5.0 package

`scripts/runtime-check.mjs --runtime <executable> --entry <installed dist/bin.js>` passed against the
package installed above, once with Node 24.15.0 and once with Bun 1.3.14. That covers the public tool
and resource surface, filesystem watcher invalidation after settling, and cross-process claim and id
allocation.

The Bun run starts `bun <dist/bin.js>` directly. It is not the `bun x --bun frontier-mcp@0.5.0`
command, and it does not change the bootstrap: its allowlist enables Bun only for 0.3.1 and 0.4.0 and
Deno only for 0.3.1. Run from the Bun-marked project, the saved 0.5.0 launcher printed
`FrontierMCP: Bun is not verified for frontier-mcp@0.5.0 on darwin/arm64; using configured Node`.

## CI

Runtime CI run [43211864369](https://github.com/51ck/frontier-mcp/actions/runs/43211864369) on
commit `7bc26d9` passed every job. That commit's tree is identical to the merge commit `9c28ac4`,
whose own `master` run was cancelled. `dac7b3d` (`v0.5.0`) differs from `9c28ac4` only by the version
bump and changelog, and has no runtime run. The package matrix packed that source and ran the runtime
check on Node 20.20.2, 22.17.1 and 24.15.0 on macOS, Linux and Windows. The real-fnm setup job in the
same run installed the registry's `frontier-mcp@0.4.0`, which is the default of
`FRONTIER_SETUP_RELEASE`. CI has therefore not run setup with a 0.5.0 server.

## Not measured

- `--apply` with 0.5.0, on any platform.
- The literal PowerShell quick-start, and the bootstrap on Windows or Linux with a 0.5.0 server.
- `bun x --bun frontier-mcp@0.5.0`, and any Deno command with 0.5.0. Deno is not installed on this
  host.
- Node 20 or 22 as the server runtime on this host. Those floors are CI evidence only.
- Managers other than fnm.
