# FrontierMCP 0.4.1 bootstrap verification

Date: **2026-09-17**. Ticket: **T92**. Host: **macOS arm64**.

This snapshot verifies the final automatic installation path against the published bootstrap
artifact. The bootstrap artifact and installed server have separate pins: the commands download
`frontier-mcp@0.4.1`, then pass `--version 0.4.0` to retain the exact server version covered by the
runtime measurements in the September 16 release follow-up.

## Published artifact

The downloaded archive was:

```text
https://registry.npmjs.org/frontier-mcp/-/frontier-mcp-0.4.1.tgz
SHA-256 69bad96519283da388573b686b91db4fd9a99c0f88c9896db2daa10f6c88e468
```

It contained `package/scripts/frontier-setup.cjs`, `package/dist/bin.js`, `package/package.json`, and
`package/README.md`.

## Literal quick-start result

An absolute Node **16.20.2** executable ran the extracted bootstrap in an isolated `HOME` and
`XDG_DATA_HOME`. The disposable consumer project contained only `.node-version` and `package.json`.
Both selected Node 16.20.2; `package.json` also declared `packageManager: "bun@1.3.14"`. The server
runtime was an explicit Node **24.15.0** executable, and the Bun runtime was
`/Users/epee/.bun/bin/bun`.

The preview used `--version 0.4.0`. It installed the exact server pin, completed the MCP verification,
and exited 0. Apply then ran with `--apply`, exited 0, and reused the same content-addressed
installation. Preview printed `Preview only`; apply did not. Apply printed `Applied Cursor user
configuration`.

The saved Cursor entry used an absolute content-addressed launcher as `command` and an empty `args`
array. The consumer project still contained exactly its original `package.json` and `.node-version`;
it gained no `node_modules` directory.

The published bootstrap's protocol check invoked the saved launcher from the Bun-marked project.
MCP initialization and discovery of all eight tools passed. The exact launcher from the isolated
Cursor configuration then ran the full `scripts/runtime-check.mjs` suite with
`FRONTIER_RUNTIME=bun`. It passed public tool and resource calls, the Ticket lifecycle, filesystem
watcher invalidation after settling, and real cross-process claim and id allocation. These checks
exercise the published 0.4.1 selector and launcher with the exact 0.4.0 server pin rather than
source-tree code.

## Evidence boundary

This is literal published-artifact evidence for macOS arm64. The PowerShell 0.4.1 quick-start was not
run locally. Windows setup behavior, including `.cmd` launchers, remains covered by the existing
representative fixtures and platform CI. fnm has real setup coverage on macOS, Linux, and Windows;
nvm, nvm-windows, Volta, asdf, and mise have fixture coverage for discovery, paths, and repair
commands rather than a literal run of every recipe on every platform.

Deno **2.9.6** remains enabled only with server **0.3.1**. The unchanged Deno 0.4.0 command failed
under its default minimum-dependency-age policy during the release verification window; the saved
launcher uses Node for that tuple. Re-evaluating a later Deno tuple is outside T92.
