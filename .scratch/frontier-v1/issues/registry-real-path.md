## Problem

The driver registry keys a workspace on the resolved path string. `repo`, a symlink to it, and `REPO` on a case-insensitive volume each build their own driver for one directory: three scan caches, three watchers, three write queues. Found while answering [[T59]].

The contract says writes are serialized per workspace. Through two spellings they are not; in 40 rounds of two concurrent comments on one Ticket nothing was lost, but only because the revision guard refused the second write.

## Acceptance criteria

- [ ] A `root` given as a symlink, in another case on a case-insensitive volume, or with redundant segments reaches the same driver as the directory itself
- [ ] The workspace line a write prints still shows a path the caller recognizes
- [ ] A test through the harness pins one driver for two spellings
