## Problem

Two Map edits have no surgical form.

Capture, 2026-11-13, read from the 1.0.0 input schema (`src/tools/edit-map.ts`): section arguments are `destination`, `notes`, `add_fog`, `graduate_fog`, `rule_out`.

1. `notes` is "Replace the Notes section". Adding one line means reading the whole section and sending all of it back with the line added. The cost grows with the section, and a concurrent writer's note is lost unless the revision check catches it. `destination` has the same shape but is short and rewritten as a unit, so it is not the complaint here.
2. `rule_out` appends a hand-ruled item under Out of scope, and nothing removes one. Fog has the pair `add_fog` / `graduate_fog`; a ruled-out item has only the first half. An item ruled out by mistake, or brought back into scope, stays in the Map until someone hand-edits the file.

This is a gap observed in the schema, not a call that failed during work.

## Done when

- [ ] One call appends text to the Notes section without the caller sending the existing Notes
- [ ] The appended value is held to the same refusals as `notes` today (`SectionBreakInValue`, GENERATED marker)
- [ ] One call removes a hand-ruled Out-of-scope item matched on its text, and fails when none match, as `graduate_fog` does
- [ ] That removal can never touch the generated dropped-Tickets block
- [ ] Both carry `expected_revision` on the rule every Map mutation follows
