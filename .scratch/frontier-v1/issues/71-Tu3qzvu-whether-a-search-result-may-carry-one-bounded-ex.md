## Question

AGENTS.md states "A Board never carries a body" as absolute. A body search (the build Ticket filed alongside this one) returns Board-shaped lines, and its recommended shape adds one line under each body-only hit: the section heading the match fell under and a fixed-width excerpt around the first match. That is body prose on a Board-shaped result.

Is the rule amended to allow a bounded excerpt, or held as written?

## What is known

From `docs/research/2026-11-13-ticket-search.md`, sections 4 and 5:

- The rule's stated reason is cost and how the read path is built: `listTickets` yields summaries, the cache holds what a Board is built from, `readTickets` is the only route to a body.
- An excerpt can respect that if the search reads files fresh through its own seam method, returns excerpts and never bodies, and caches nothing.
- Without an excerpt the caller fetches every hit's body to learn whether it is relevant. For the query `watcher`, 13 body-only hits are roughly 57KB of `get_tickets` output against 3.4KB with one excerpt line each. That figure is inferred from measured file sizes; the fetch was not run.
- The fallback if the rule holds: name the matched section heading and give no excerpt. With `Tvndqat` (partial body reads) the caller could then fetch that one section per hit.

## Done when

- [ ] The rule in AGENTS.md either stands as written or is reworded to say exactly what a search result may carry and how wide
- [ ] If amended, the bound is a number, and the read-path constraint (fresh read, nothing cached, never a whole body) is written beside it
- [ ] The body-search Ticket's criteria are updated to match the answer
