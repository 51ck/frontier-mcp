## Problem

`update_ticket` has no way to change the prose a Ticket was created with. Its body edits are `tick`, `comment` and `resolve.answer`; there is no argument for the Problem text or for the criteria list. Once `create_tickets` has written a body, the only routes to correct it are a comment that contradicts the body, or a hand edit of the file.

Capture, 2026-11-13, read from the 1.0.0 input schema (`src/tools/update-ticket.ts`): arguments are `id`, `claim`, `resolve`, `drop`, `reopen`, `release`, `status`, `triage`, `blocked_by`, `comment`, `tick`, `drop_keys`, `title`, `kind`, `type`, `root`.

Cases the consumer could not express:

- A reviewer finds a case mid-work that should gate the Ticket. It can be written as a comment, but it cannot become a checkbox, so `tick` can never record it as done.
- A Ticket filed with a claim marked "inferred, not tested" (`Tlgyn13`) is later tested. The Problem section cannot be corrected to say what was found.
- A criterion turns out to be worded wrongly. It can be neither reworded nor removed.

Not wanted: a whole-body replace. It costs the most tokens, it can clobber the comment log and already-ticked boxes, and it widens every small fix into a race with any other writer.

Constraint: eight tools, permanently — optional arguments on `update_ticket`.

## Done when

- [ ] One call appends one or more acceptance criteria as unticked checkboxes to the Ticket's existing criteria list, leaving every other line byte-identical
- [ ] Appending to a Ticket with no criteria list has a decided, documented outcome
- [ ] One call replaces a single `##` section named by its heading, up to the next `##`, leaving every other section, the comment log and the answer byte-identical
- [ ] Naming a section that does not exist fails and writes nothing
- [ ] Whether the answer section and the comment log may be targeted by the section replace is decided and refused or allowed out loud
- [ ] A replacement value containing a `##` line is refused, on the rule `edit_map` already applies (T96)
- [ ] Both edits carry the revision check every other write does

## Agent Brief

**Category:** enhancement
**Summary:** `update_ticket` gains `add_criteria`, which appends unticked acceptance criteria.

**Scope change at triage, 2026-11-13, agreed with the maintainer:** this Ticket is narrowed to adding criteria. Replacing a body section is split out to the decision `T500woi`. The body's criteria about section replace (the third through sixth) no longer belong to this Ticket; the title was changed to match.

**Current behavior:**
A Ticket's criteria list is fixed at creation. A case found mid-work can be recorded only as a comment, which `tick` cannot mark done.

**Desired behavior:**
- `add_criteria` is an array of non-empty single-line strings. Each is appended as `- [ ] <text>` after the last existing checkbox of the Ticket's criteria list.
- Every other line of the body stays byte-identical, on the rule `tick` already follows.
- A Ticket with no checkbox list gets a new `## Acceptance criteria` section holding them, placed before the answer and the comment log if those exist.
- A value containing a line break is refused, as is one that duplicates an existing criterion after whitespace collapse (the comparison `tick` uses). Nothing is written.
- `add_criteria` and `tick` in one call are both applied, and a criterion added by the call may be ticked by it.
- Allowed on a resolved Ticket: a late finding is still a record of work.

**Key interfaces:**
- The `update_ticket` input schema and the annotations group in its description
- The edit vocabulary at the storage seam, which gains one edit
- The body serializer that already locates checkboxes for `tick`

**Acceptance criteria:**
- [ ] Appending to a Ticket with a criteria list changes only the added lines
- [ ] Appending to a Ticket with none creates the section in the stated place
- [ ] A multi-line value and a duplicate are each refused with a named error, file untouched
- [ ] `add_criteria` with `tick` on the same new criterion works in one call
- [ ] The write carries the revision check
- [ ] On a Foreign Ticket with no parseable fence it follows the existing normalize-on-write rule
- [ ] The tracker doc's tool table names it, and its revision number is raised

**Out of scope:**
- Rewording, removing or reordering criteria
- Any other body edit (`T500woi`)
