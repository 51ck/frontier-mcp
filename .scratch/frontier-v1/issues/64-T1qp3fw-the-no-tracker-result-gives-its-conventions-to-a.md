## Problem

When `.scratch/` does not exist, `list_efforts` ends with `conventions: frontier://tracker-doc` (T105). Reading that URI needs the client to expose MCP resources to the model, which is a separate client tool and not always present.

Capture, 2026-11-13, published `frontier-mcp@1.0.0`:

```
list_efforts { root: <repo with no .scratch/> }
-> root: <path> (resolved by root argument)
   no tracker here: .scratch/ does not exist
   start one: create_tickets { effort, create: true, tickets } or edit_map { effort, create: true, destination }
   conventions: frontier://tracker-doc
```

In the Claude Code session that ran this, the resource-reading tools were deferred and at one point unavailable entirely, so the pointer could not be followed with the tools at hand. An agent meeting FrontierMCP for the first time is the reader this line is for, and it is the one least likely to know another route to the document.

This is inferred from the smoke test rather than something that blocked work: the consumer already knew the conventions from this repository's own docs.

Needs triage against T61 (the onboarding tool — what it serves and what it writes) in `frontier-onboarding`, which may own the answer.

## Done when

- [ ] An agent with tools only, no resource access, can get from the no-tracker result to the conventions it needs to create a first Ticket correctly
- [ ] The no-tracker result stays short, and a populated tracker's results are unchanged
