**Category:** enhancement

**Summary:** Everything a consumer or a contributor reads still describes minted ids. It is brought in line with ADR 0008 in one pass, with the upgrade note 2.0 needs.

**Current behavior:** The glossary defines a Ticket as identified by an id of the form `T<n>`. The tracker document, the root contract, the spec and the README describe the id pattern, temporary keys, handles and the minting rules.

**Desired behavior:**

- The glossary defines a Ticket's name, and drops or redefines the terms that only served minted ids.
- The tracker document tells an agent how to choose a name (one to three words, what the Ticket is, not what it does to the code), how to reference one inside and across Efforts, how a hand-written file is named, and what to do when two branches chose the same name. Its revision number is raised.
- The root contract's sections on ids, patterns, guards, handles and duplicates are rewritten to the shipped behaviour, and ADR 0006's supersession note loses its "not yet built" wording, as does ADR 0008's.
- The spec's tool surface table and the README match the new `create_tickets` shape.
- A 2.0 upgrade note states the breaking changes and that existing ids keep working with no action.
- GitHub issue #53 is answered with the outcome. Posting that reply needs the owner's go-ahead.

**Key interfaces:** the tracker document served as an MCP resource and shipped in the package; the tool descriptions, which are context in every session and must stay short.

**Acceptance criteria:**

- [ ] No shipped document describes minting, the id pattern or temporary keys as current behaviour
- [ ] The tracker document's revision is raised and the form check still passes
- [ ] The token measurements asserted by the read-path cost test are re-measured with named Tickets and the assertions updated to the new figures
- [ ] The upgrade note is reachable from the README

**Out of scope:** renaming this repository's own existing Tickets.
