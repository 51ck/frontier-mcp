> *This was generated by AI during triage.*

**Category:** enhancement

**Summary:** Once nothing mints, the configurable id pattern and everything that served it is dead weight and is deleted.

**Current behavior:** The workspace's `frontier.yml` sets `id_pattern`; the driver compiles it into a minting plan, takes guard files for a counted pattern, refuses every write under a broken config, and warns on each creation under a counted-only pattern.

**Desired behavior:**

- `id_pattern` is no longer read. A workspace that still sets it gets one grouped Board warning saying it is ignored since 2.0. No write is refused because of that file.
- No guard file is created. Guard files left by 1.x are ignored and never deleted by the server.
- The creation-time warning about a counted pattern is gone.
- The duplicate warning no longer names a pattern as a likely cause.
- Whether a string is an existing Ticket's id is answered by lookup, not by shape.

**Key interfaces:** the storage driver's id-shape predicate, minting plan and workspace-config warnings; the `create_tickets` result rendering.

**Acceptance criteria:**

- [x] A workspace with a valid, an invalid and an unparseable `frontier.yml` each accept writes, and each shows the one warning
- [x] No file other than Ticket, Map and Spec files is written by any tool
- [x] The tests that pinned minting, guards and the pattern warning are removed or rewritten, and the suite passes
- [x] Existing ids of every shape that 1.x minted still resolve

**Out of scope:** migrating or renaming any existing Ticket.

## Answer

Built on `feat/ticket-names` together with [[Tjgohfq]]. Independently reviewed: no dead exports in `src/`, and `InvalidWorkspaceConfig` had no other thrower.

- **Warning**, on Boards only, for a set `id_pattern` or an unparseable file: `.scratch/frontier.yml is ignored since FrontierMCP 2.0: no id is minted, so id_pattern does nothing and no write depends on this file — it can be deleted`. A `frontier.yml` that parses and sets no `id_pattern` is silent.
- **Guard files** from older versions (`.frontier-id-N-<n>.guard`, `.frontier-id-<id>.guard`) are never read, counted or deleted.
- The revision-keyed claim guard of ADR 0004 is a different mechanism and stays.
- The duplicate warning names no pattern.

Not done here: the packaged runtime check still drives the 1.x contract and fails ([[Tijope9]]); the shipped tracker document, README, glossary and spec still describe the pattern ([[Tfknlw5]]).
