> *This was generated by AI during triage.*

**Category:** enhancement

**Summary:** Once nothing mints, the configurable id pattern and everything that served it is dead weight and is deleted.

**Current behavior:** The workspace's `frontier.yml` sets `id_pattern`; the driver compiles it into a minting plan, takes guard files for a counted pattern, refuses every write under a broken config, and warns on each creation under a counted-only pattern.

**Desired behavior:**

- `id_pattern` is no longer read. A workspace that still sets it gets one grouped Board warning saying it is ignored since 2.0. No write is refused because of that file.
- No guard file is created. Guard files left by 1.x are ignored and never deleted by the server.
- The creation-time warning about a counted pattern is gone.
- The duplicate warning no longer names a pattern as a likely cause.
- Whether a string is an existing Ticket's id is answered by lookup, not by shape.

**Key interfaces:** the storage driver's id-shape predicate, minting plan and workspace-config warnings; the `create_tickets` result rendering.

**Acceptance criteria:**

- [ ] A workspace with a valid, an invalid and an unparseable `frontier.yml` each accept writes, and each shows the one warning
- [ ] No file other than Ticket, Map and Spec files is written by any tool
- [ ] The tests that pinned minting, guards and the pattern warning are removed or rewritten, and the suite passes
- [ ] Existing ids of every shape that 1.x minted still resolve

**Out of scope:** migrating or renaming any existing Ticket.
