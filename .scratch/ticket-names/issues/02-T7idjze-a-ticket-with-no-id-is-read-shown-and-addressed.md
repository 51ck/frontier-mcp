> *This was generated by AI during triage.*

**Category:** enhancement

**Summary:** The read path names a Ticket by ADR 0008's derivation, and every reader accepts and shows that name.

**Current behavior:** A Ticket file with no `id` is addressed by an `<effort>#<order>` handle that cannot be used as an Edge, and is counted under a `no id` warning. Edges are ids resolved repo-wide.

**Desired behavior:**

- A Ticket's name is its `id` when it carries one, the id its prose declares when it has no parseable fence, and otherwise its file stem with a leading `<digits>-` removed.
- A Board shows each Ticket of the Effort by bare name. An Edge to a Ticket of the same Effort shows bare; an Edge into another Effort shows as `<effort>.<name>`, which is also valid input.
- An Edge stored as a bare name resolves within the Ticket's own Effort, a stored `<effort>.<name>` resolves across Efforts on the longest known Effort slug, and anything else resolves as an existing id repo-wide.
- `get_tickets` and `update_ticket` accept a full name, an existing id, or a bare name that exactly one Ticket in the workspace has. An ambiguous bare name is refused with the candidates named.
- Names compare without regard to case.
- Two files in one Effort that reduce to the same name are a duplicate under the existing duplicate rules.
- The `<effort>#<order>` handle is no longer produced or accepted.
- Existing Tickets with ids read, render and resolve exactly as before.

**Key interfaces:** the `TicketSummary` identity field and the storage driver's lookup by handle; the Board's Edge rendering; the Frontier computation, which must treat a named Ticket as addressable.

**Acceptance criteria:**

- [x] An Effort of hand-written files with no `id` shows every Ticket by name, and each can be fetched and updated by that name
- [x] A bare Edge between two such Tickets is satisfied when its target resolves, and the dependent joins the Frontier
- [x] A cross-Effort Edge renders in a form that works when pasted back as input
- [x] An ambiguous bare name is refused with every candidate's full name
- [x] A workspace of existing id-carrying Tickets produces byte-identical Boards before and after
- [x] Two stems reducing to one name are warned on read and refused on write

**Out of scope:** creating Tickets by name; the typo rule; Board ordering; removing the id pattern.

## Answer

Built on branch `feat/ticket-names`, not committed. 433 tests and `pnpm run check` pass.

- Handles `<effort>#<order>`, the `.2` suffix and the `no id (N)` warning are gone.
- One definition of a duplicate, keyed on the case-folded full name, used by both layers.
- Tool input: a full name wins; a string that is an id and also another Ticket's bare name is refused with both named.
- A real `migrate_effort` refuses on a duplicated name; the preview reports it and still shows the plan.
- Checked by builder and reviewer independently: every tool's output on this repository's own `.scratch/` is byte-identical before and after.
