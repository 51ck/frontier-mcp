**Category:** enhancement

**Summary:** The owner chose, on 2026-11-15, to drop "Foreign by fence" altogether. It replaces the provisional answer on [[Ti75suj]], which kept the predicate and left an asymmetry between Tickets with and without an `id`.

**Current behavior:** A fence that parses is Foreign when it carries no `id` and a key outside the schema. Such a Ticket's fields are already read from the fence, so being Foreign-by-fence changes only two things: the Board counts it apart, and `get_tickets` shows its fence whole rather than entry by entry. A Ticket with an `id` and the same stray key is not Foreign and shows only its Unimported entries.

**Desired behavior:**

- A Ticket is Foreign only when it has no parseable fence, so its fields were inferred from prose.
- A key outside the schema is an Unimported key on any Ticket, with or without an `id`. `get_tickets` shows Unimported keys the same way on every Ticket: each entry sliced from the file's own text.
- The Board carries one grouped warning line counting the Tickets that hold Unimported keys, with no handles listed, replacing the line that counted foreign-fenced Tickets. A workspace with none shows nothing.
- `drop_keys` works as today on every Ticket. Dropping the last Unimported key removes the Ticket from the count.
- Nothing distinguishes a Ticket by whether it carries an `id` except its name.

**Key interfaces:** the two Foreign flags on `TicketSummary`, of which the fence one goes; the Foreign predicate in the markdown driver; the Board's warnings block; `get_tickets`' Unimported section.

**Acceptance criteria:**

- [x] A fenced Ticket with a stray key and no `id`, and one with a stray key and an `id`, are reported identically apart from their names
- [x] Neither is counted as Foreign; both are counted in the Unimported line
- [x] A Ticket with no parseable fence is still Foreign, still normalized by a write, and still counted as before
- [x] `drop_keys` on the last Unimported key clears the Ticket from the count
- [x] ADR 0007 is amended to the new predicate, and its account of how a Ticket leaves the Foreign set is rewritten
- [x] The glossary entry for Foreign, where it exists, matches

**Out of scope:** a bulk way to drop Unimported keys across an Effort, which is [[T86]]'s question.

## Answer

Built on `feat/ticket-names`. 640 tests and `pnpm run check` pass. Reviewed by the lead from the diff, not by an independent reviewer.

- `TicketSummary.foreignFenced` is replaced by `hasUnimportedKeys`, set from the frontmatter the scan already parses, so the Board still reads no body.
- Board line: `N/M Tickets hold Unimported keys — frontmatter outside the schema; get_tickets shows them, update_ticket drop_keys removes them.`
- `get_tickets` shows only the unimported entries on every Ticket. The whole fence is still shown as a fallback when an entry cannot be cut out cleanly, and that no longer depends on `id`.
- `migrate_effort` is unchanged in code; a fenced id-less Ticket with stray keys now reports `mint` where it reported `normalize+mint`.
- ADR 0007 is amended and dated; ADR 0008's closing paragraph no longer calls the predicate unsettled.
- The glossary has no Foreign entry, and its Legacy ticket and Unimported keys entries already agree, so it is unchanged.
