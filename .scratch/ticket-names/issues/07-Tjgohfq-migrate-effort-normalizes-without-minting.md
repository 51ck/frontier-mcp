**Category:** enhancement

**Summary:** Migration loses its minting step and keeps the rest: normalizing an Effort's files and resolving the Edges that only migration can resolve.

**Current behavior:** `migrate_effort` mints an id for every Ticket without one, resolves bare sort-order Edges to the minted ids, and reports the plan.

**Desired behavior:**

- No id is minted. A Ticket is reported and written under the name the read path already gives it.
- A bare sort-order Edge such as `01` is rewritten to the name of the Ticket whose file carries that prefix.
- Files are never renamed, as today.
- The preview and the real run report the same names, since nothing is drawn or counted.
- How a foreign-fenced Ticket is marked as accepted follows the decision on the Foreign predicate.

**Key interfaces:** the `migrate_effort` report rendering and the driver's migration pass.

**Acceptance criteria:**

- [x] Migrating the two verbatim fixture Efforts mints nothing and leaves every Ticket addressable by name
- [x] Sort-order Edges resolve to names and the affected Tickets reach the Frontier as they did under minting
- [x] Preview and real run agree line for line on names
- [x] An Effort that already carries ids is left with those ids

**Out of scope:** the open migration Tickets in `migration-field-report` that concern status inference.

## Answer

Built on `feat/ticket-names` together with [[Td5xifi]]. 631 tests, `pnpm run check` and `pnpm run build` pass; independently reviewed.

- **Report:** header `alpha: migrated 3, unchanged 1`, lines flagged `normalize`, `edges` or both. The preview header counts only Tickets a real run would write. Preview and real run are identical below the header.
- **A sort-order Edge stays dangling** when two files carry the prefix, the target's name is not its alone, the digits already name a Ticket, or it would point at the Ticket itself. Those are listed in one grouped report line.
- **Numeric-looking text:** an `id` and a `blocked_by` entry that YAML reads as a non-string scalar are both taken as their source text, so `id: 02` and `[02]` agree, and writes quote them. Accepted cost: a quoted `"2"` Edge no longer matches a file whose id is written `02`. Only hand-written files can be affected; 1.x never wrote such an id.
- **A fenced file gaining only a rewritten Edge** gets what `update_ticket blocked_by` guarantees, not byte identity.
- **A full-name Edge from another Effort** keeps resolving after migration, since no id replaces the name.

Unchanged from 1.x and not fixed here: a real run is not all-or-none and carries no revision check (reads all happen before any write, and a rerun completes the rest); a file with an unparseable fence loses that fence's text when normalized; a two-Ticket cycle formed by sort-order Edges is written and left to the Board.
