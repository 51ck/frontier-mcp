> *This was generated by AI during triage.*

**Category:** enhancement

**Summary:** With names chosen by callers there is no id shape to test a reference against, so a probable typo is told from a forward reference by distance.

**Current behavior:** A reference is refused when it is neither a well-formed id nor a declared temporary key. A well-formed id that does not exist is accepted as a dangling Edge.

**Desired behavior:**

- On `create_tickets` and on `update_ticket` `blocked_by`, a reference that resolves to nothing is compared with the names it could have meant: the Tickets of the same Effort, the names declared in the same call, and for a full name the Tickets of the named Effort.
- Within two edits of one of them, the write is refused and names the near one.
- Further than two edits, it is stored as a dangling Edge and shown on the Board as today.
- A reference to an unknown Effort in a full name is a dangling Edge, not a refusal.
- The server stores an Edge in the shortest form that resolves: bare within the Effort, full across.

**Key interfaces:** the reference check shared by the two write paths, above the storage seam; the failure type for a probable typo.

**Acceptance criteria:**

- [x] A one-character slip in a sibling's name is refused and the message names the sibling
- [x] A transposition of two adjacent characters is refused the same way
- [x] A reference unlike any existing name is stored and shows as dangling on the Board
- [x] A full name written for a Ticket of the same Effort is stored bare
- [x] Existing dangling Edges in a workspace do not stop unrelated writes

**Out of scope:** refusing near names between siblings at creation, which ADR 0008 rules out.

## Answer

Built on `feat/ticket-names`. 533 tests and `pnpm run check` pass.

- **Threshold, changed from the brief after review:** near means a distance between 1 and `min(2, floor((L - 1) / 3))`, `L` the shorter string. Names up to 3 characters are never a near miss, 4 to 6 allow one edit, 7 and up allow two. "Two edits" at length 5 refused a forward reference to `parse` beside an unrelated `purge`. ADR 0008 states the bands.
- **A forward reference in a series is refused**: an unwritten `step-4` beside `step-3`. The rule stays; the message says to declare the Ticket in the same call or create it first.
- **Edges already stored on the Ticket are exempt**, so an existing dangling Edge can be kept while the list is edited.
- **What is written is what was settled on a fresh read**, on both write paths. `update_ticket` pays one extra workspace walk, only when `blocked_by` is supplied. This added an optional `settle` to the storage seam.
- A Board form pasted back (`ledger@beta`) is refused naming `beta.ledger`.

Not done: Unicode normalization of hand-made stems, so a decomposed and a precomposed spelling of one name are a near miss of each other. The fresh-read test was not run against the old code to confirm it fails there.
