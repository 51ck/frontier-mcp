> *This was generated by AI during triage.*

**Category:** enhancement

**Summary:** `create_tickets` stops minting. Each entry carries the name the caller chose, and the file is written at the path that name implies.

**Current behavior:** Each entry may carry a temporary `key`; the server mints an id from the workspace's pattern, numbers the file, and resolves keys to ids.

**Desired behavior:**

- Each entry requires `name`. `key` is gone, and passing it is refused.
- `blocked_by` names a sibling by its `name`, a Ticket of the same Effort by bare name, another Effort's Ticket by full name, or an existing id.
- The file is `<name>.md` in the Effort's `issues/`, with no sort-order prefix, and its frontmatter carries no `id`.
- A name is refused, with the reason, when it breaks the grammar (one to three hyphen-joined words of lowercase letters and digits, starting with a letter, at most 24 characters, no dot), is reserved (`lock`, the YAML words `true false null yes no on off`, Windows device names), is already a Ticket of that Effort, equals an existing id in the workspace, or repeats within the call. Comparison ignores case.
- The batch stays all or none.
- The result lists the full name of each created Ticket.

**Key interfaces:** the `create_tickets` input schema and description; the driver's batch create and its validate hook for cycles.

**Acceptance criteria:**

- [x] A batch with sibling Edges by name creates every file at the expected path with no `id` field
- [x] Each refusal above is exercised and names the offending entry and the rule
- [x] One refused entry leaves the workspace untouched
- [x] A cycle through a newly named Ticket is refused
- [x] Two processes creating the same name in one Effort at once leave exactly one file and one refusal
- [x] Creating into an Effort that holds only id-carrying Tickets works, and Edges from the new Ticket to those ids resolve

**Out of scope:** the typo rule for Edges to names that do not exist; removing the id pattern machinery; documentation.

## Answer

Built on branch `feat/ticket-names`, not committed. 506 tests and `pnpm run check` pass on performance cores.

- **Names:** grammar, reserved words, taken in the Effort, equal to an existing id, repeated in the call — each refused naming the entry and the rule, case ignored.
- **Exclusive create:** files are staged, every target is checked against a fresh listing, then each is hard-linked into place. A hard link refuses an existing target, so two processes creating one name leave one file and one refusal.
- **Rollback never deletes another session's write.** A loser unlinks a file only while the path still holds its own inode. If another session has already rewritten one, it stays and the failure names it: the batch is then not fully undone. This is a deliberate weakening of all-or-none in a three-way race.
- **Needs hard links.** On a filesystem without them creation fails with a message saying so; there is no fallback, because an exclusive open plus write would let a reader see a half-written Ticket.
- **A completed creation always reports success**, even when the scan that renders its Edges fails.
- **Path traversal through `effort` is closed** for every Effort-addressed call. It was present in 1.0.0: `effort: "../../escaped"` with `create: true` wrote outside the workspace.

Carried forward: Edges are stored as given ([[Tyughqp]]); `isId` and the pattern module have no caller above the seam except through migration ([[Td5xifi]], [[Tjgohfq]]); the cross-process test of the counted guard was removed with create-time minting, so that guard is covered in-process only until migration stops minting. The hard-link failure message has no test.
