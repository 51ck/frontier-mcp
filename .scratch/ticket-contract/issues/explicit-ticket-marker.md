## What to build

A file is a Ticket when its frontmatter carries `frontier: ticket` and it sits where the layout contract says Tickets live. The marker has no version. The server validates a marked file against the schema it ships and works only with those that pass.

- **Valid**: processed as today. The existing field set and workflow requirements are kept; this is not a schema redesign.
- **Marked but malformed**: excluded from normal operations (Board, Frontier, writes) and reported through structured diagnostics that name the file, the field and what was expected. It stays discoverable through those diagnostics so an agent can fix it by hand.
- **Unrelated Markdown** (a README, notes): ignored.
- **Nothing is auto-modified**: no file is normalized, migrated, marked or moved by the server.

Removed with this: parsing a Ticket from prose, and automatic migration. Only explicitly supported locations are inspected; an Effort is never walked recursively. A marked file in a known unsupported placement gets a diagnostic and is never treated as a Ticket.

Source: the owner's decision on [[T79]]. Which fields are required for validity beyond the current workflow rules is still under discussion; build to the current set and do not invent new requirements.

## Acceptance criteria

- [ ] A `.md` in a supported Ticket location with `frontier: ticket` and valid frontmatter is on the Board; the same file without the marker is not
- [ ] A README and a notes file beside Tickets are not Tickets, are not counted, and are byte-identical after every tool has run
- [ ] A marked file with an invalid field is absent from the Board and the Frontier, every write to it is refused, and a diagnostic names its file, the field and the expected value
- [ ] A marked file whose frontmatter does not parse is diagnosed as such, not silently unmarked
- [ ] Board warnings about excluded files stay grouped, never one line per file
- [ ] A marked file in a known unsupported placement is diagnosed with where it was expected; nothing is moved
- [ ] No directory outside the supported locations is read; a test with a deep tree under an Effort proves it
- [ ] `create_tickets` writes the marker, and a created file passes the same validation
- [ ] The prose parser, the Foreign flag and write-time normalization are gone, with their tests and the two verbatim fixture Efforts' role restated
- [ ] `test/read-path-cost.test.ts` still pins the token argument on input that is valid under the new rule
- [ ] The tracker doc (revision raised), `CONTEXT.md`, `AGENTS.md` and README state the rule; an ADR supersedes ADR 0007 and amends ADR 0008
- [ ] This repository's own Tickets are valid under the rule before the change merges, by a one-off edit outside the package
