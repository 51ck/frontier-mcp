## What to build

A Ticket may carry an optional `tags` field: a list of arbitrary strings. An agent sets tags when creating a Ticket, replaces them on an update, and sees them when reading it. Tags have no effect on Status, on Edges or on the Frontier.

Filtering by tag is not part of this; it is tracked in `frontier-search`.

## Acceptance criteria

- [ ] `create_tickets` accepts `tags` per Ticket and writes them
- [ ] `update_ticket` replaces a Ticket's tags, and an empty list clears them
- [ ] `get_tickets` shows a Ticket's tags; a Ticket without any shows nothing extra
- [ ] A Ticket with no `tags` key is valid, and is written without one
- [ ] A `tags` value that is not a list of strings makes a marked Ticket malformed, with a diagnostic naming the field
- [ ] Changing tags never changes what is takeable; a test pins it
- [ ] Whether a Board line shows tags is decided and measured in tokens, or explicitly left to `frontier-search`
- [ ] The schema `check-tracker` returns includes `tags` if that tool has landed
- [ ] The tracker doc and glossary describe tags; the doc's revision is raised
