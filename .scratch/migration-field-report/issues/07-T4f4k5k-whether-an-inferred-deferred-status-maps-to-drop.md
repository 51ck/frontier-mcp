## Question

AGENTS.md states that `superseded` and `deferred`, read from a Foreign file's `Status:` line, map to `dropped`, on the reasoning that inference may lean conservative because it is guessing. `T83`'s field report shows the cost of that for `deferred`: `deferred to 0.6.0 — code on feat/three-r185` was scheduled work, and it was marked terminal and out of scope, which also orphans every Ticket that depends on it.

Should `deferred` map to `open` instead?

## What is known

- `dropped` orphans dependents: they are never takeable and the Board says so. Nothing is taken wrongly, but real work disappears from the Frontier.
- `open` keeps the Ticket and its dependents in the graph, and makes the deferred Ticket itself takeable unless something blocks it. An unattended run could then start work someone had deliberately postponed.
- Which direction is "conservative" depends on which mistake is worse: hidden work or premature work.
- Once `T83` lands, migration lists every Ticket whose Status was guessed, with the original string beside it. That makes either default reviewable, and may make the choice matter less.
- `superseded` is not in question here: the report's complaint about it is the lost successor reference, not the terminal state.
